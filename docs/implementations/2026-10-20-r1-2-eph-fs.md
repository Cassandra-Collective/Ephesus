# R1.2 — `eph-fs`: the one write path, the append-only log, and a home that knows whose it is

**Gymnasium:** GYM-013 (the rewrite)

## 1. Problem / motivation

Invariant 3 says a file another process reads is written whole or not at all, and
invariant 5 says append-only stays append-only. In the Rust tree, `clippy.toml` already
refuses every direct write outside the one crate allowed one. This package is that
crate. It provides the write path SDD-RUST §4.0 rule 5 names: `write_atomic`, and
`AppendLog` for the book of record. It also adds the harness home's first-boot
behaviour. R1.3 (`eph-git`) and R1.4 (`eph-agora`) build on all three.

**The home could not simply be ported.** The TypeScript build keeps running from
`~/.ephesus` until R14, and after R1.1 six of its files are formats the Rust build
cannot read. A Rust build that created directories, seeded files or wrote a marker there
would be writing into the frozen build's live home. The Architect decided that such a
home is reported once and left exactly as it is.

## 3. Implementation approach

### 3.1 `write_atomic`

The bytes go to `.<name>.<8 hex>.tmp` in the target's own directory, because a rename
cannot cross filesystems. The temporary file is created new (`create_new`), so the
write can never land on a live path. It is written in full, synced, and renamed over the
target. On POSIX the directory is synced as well, so the rename itself survives a power
cut. On a failure the temporary file is removed and the target keeps its old bytes.

The retry around the rename is `retry_rename(rename, transient, sleep)`: the attempt,
the judgement and the wait are all parameters. It makes one attempt, then one more after
each entry of a fixed schedule, `WAITS`, and stops at the first success or the first
failure judged permanent. There is no clock, so the waits and their total are tested
with a recording `sleep` on every platform, and only one test needs a real hold.
`is_transient(raw, on_windows, destination_is_dir)` takes the platform as a parameter
for the same reason.

The first draft bounded the loop by a clock instead: attempt while the time spent was
under the budget. Mutation round 1 found three changes to that condition that made the
loop run forever. A fixed schedule cannot: its length is a constant, so no change to a
comparison can make it endless.

### 3.2 `AppendLog`

`append(render)` asks the caller to render the line for the next `seq`, so the line's
format stays `eph-schema`'s while the writer owns the numbering. A rendered line that
holds a newline is refused, because it would become two lines.

Before writing, the writer checks rotation. It then checks whether the file ends
mid-line, the torn tail of a killed writer; if so it starts with a newline, leaving the
torn bytes exactly as they are. Then it appends and syncs.

Rotation renames the live file to `log-archive/log-<first seq>.jsonl`. A rotation that
cannot happen is returned as `Rotation::Skipped` with its reason, and the line still
lands. There are three such cases: no readable line to name a segment by, a segment of
that name already existing, or the rename failing.

### 3.3 The home

`open(root, now)` decides from what is on disk:

| Found | Verdict | Written |
|---|---|---|
| Nothing at `root` | a new home | `home.json` first, then the directories, `config.json` and the two seeds |
| An empty directory | a new home | the same |
| A directory with a valid `home.json` | this build's home | missing directories and seeds only |
| `home.json` that does not parse | refused, `home/marker-damaged` | nothing |
| Anything else, including one stray file | refused, `home/typescript-era` or `home/not-a-home` | nothing |
| A file | refused, `home/not-a-home` | nothing |

A file at `root` is refused first. Otherwise `open` creates `root` if it is missing, a
no-op for a directory that exists, and then decides from the directory's entries alone:
none, `home.json`, or anything else. So a missing path and an empty directory take the
same branch, because after `create_dir_all` they are the same thing. The first draft
checked for a missing path separately, and mutation round 1 showed no test could tell
that check from the one after it.

The TypeScript names (`agora`, `config.json`, `prompts`, …) only choose between the two
refusal messages. The verdict comes from the marker alone, so a short or wrong list
cannot cause a write. A refusal names the fix: set `EPH_HOME` to a directory that does
not exist yet.

Seeding writes `gate-policy.json` and `authority.json` from the bundled files when they
are absent, and reports each as `home/seeded-config:<file>`. An existing file is never
written. If its `seededFrom` is older than the shipped default's, the drift is reported
as `home/policy-behind:<file>` and nothing changes. If it has no `seededFrom`, it was
made by hand and is not compared. If it cannot be read, that is reported as
`home/unreadable-policy:<file>`. Every condition is returned to the caller, the boot
that reports it.

## 4. Mathematical / statistical details

**The retry's waits.** `WAITS` is 5, 10, 20, 40, 80, 100, 100, 100, 45 ms: 5 ms
doubling to a cap of 100 ms, then 100 ms, with the last wait cut so the sum is the
budget:

$$\sum_{i=1}^{9} w_i = 5 + 10 + 20 + 40 + 80 + 3 \times 100 + 45 = 500\ \text{ms}.$$

There are 9 waits, so 10 attempts at most: one before the first wait and one after each.
A hold that never ends therefore costs exactly 500 ms of waiting, plus the time of the
10 attempts themselves, before the write fails. The TypeScript build's clock-bounded
loop could overshoot by up to one wait, 600 ms in all. Tests pin the sum against
`RENAME_BUDGET`, the waits a hold released after the sixth attempt sees
(5, 10, 20, 40, 80 and 100 ms), and the 10 attempts and 500 ms of a hold that never
ends.

**The cost of a synced append**, measured on win32 (Windows 11, NVMe), 1000 appends of a
70-byte line, each opening the file for append:

| | Total | Per append |
|---|---|---|
| Without `sync_data` | 222.8 ms | 0.22 ms |
| With `sync_data` | 1022.7 ms | 1.02 ms |

So syncing adds about 0.8 ms a line on this machine.

## 5. Design decisions

- **Measured, not ported: the Windows codes.** A destination held by a handle that does
  not share delete access fails the rename with OS error 5, and the target keeps its old
  bytes. A held source fails it with error 32. A destination that is a directory also
  gives 5, so that case is checked before waiting. A holder that does share delete lets
  the rename through. Node's `EPERM`/`EACCES`/`EBUSY`, which the TypeScript build keyed
  on, are not codes a Rust `io::Error` carries on Windows.
- **A schedule of waits, not a clock.** The budget and backoff are the TypeScript
  build's, but the loop is bounded by the length of `WAITS` rather than by time spent.
  A loop bounded by a clock can be made endless by a one-character change, which
  mutation round 1 showed three ways. It also needs a fake clock to test. A constant
  schedule cannot be made endless, and a recording `sleep` tests it. The cost: the
  time the 10 attempts themselves take is not counted against the budget, so the
  bound is on the waiting, not on the whole call.
- **Nothing is retried off Windows.** POSIX `rename` does not fail for an open handle,
  and error 32 there is an unrelated one.
- **A synced append, at 1.02 ms against 0.22 ms**, so the book of record survives a power
  cut. The TypeScript build never synced.
- **The log writer does not own the line's format.** A `seq_of` function and a render
  closure keep `eph-fs` free of `eph-schema`'s log line, which R1.4 will pass in.
- **An empty directory is the one unmarked directory adopted.** A TypeScript home is
  never empty, since that build makes its directories before it writes anything. So
  allowing `mkdir x && EPH_HOME=x` costs no safety.
- **The marker first.** A boot killed while making a home leaves a marked, half-made
  home, which the next boot finishes. If the marker came last, a killed boot would leave
  an unmarked directory that the next boot refuses as someone else's.
- **Residual, stated:** a crash between writing a temporary file and renaming it leaves
  `.<name>.<8 hex>.tmp` beside the target. Nothing sweeps these yet. A sweep is safe
  only once boot knows no other harness is live (ADR-0034's probe), so it belongs to the
  boot that runs that probe.
- **The platform gap, by design.** The POSIX directory sync never runs on Windows, so
  `eph-fs` measures two lines lower there: 96.00% against 96.57% on Linux. Its floor is
  therefore the Windows figure. That gap is what the Architect asked the floors to show.

The 10 lines no test reaches, from `cargo llvm-cov report --show-missing-lines`:
- the POSIX directory sync (5 lines), which does not run on Windows;
- two of rotation's skip reasons: the live file cannot be read, and the rename that
  seals it fails (2 lines);
- an I/O failure while seeding `gate-policy.json` or `authority.json` (2 lines);
- `AppendLog::open` on a path with no parent directory (1 line).

**A real hold, on Windows.** A destination held by a read handle without delete
sharing, released after 120 ms, is waited out and the write lands. Held past the budget,
the write fails with error 5 after at least 500 ms, the target keeps its bytes, and the
temporary file is gone.

**A refused home is left byte for byte.** The tests snapshot every file and directory,
with its bytes, before and after `open` on each kind of refused directory. That covers a
directory with `prompts/` and `agora/` (what the TypeScript build makes first), one with
a stray `.DS_Store`, a damaged marker, and a file. In every case the snapshots are equal.
A second `open` of a made home changes nothing, the marker's timestamp included.

**Linux, in WSL (Ubuntu, toolchain 1.96.0-x86_64-unknown-linux-gnu), over exactly the
files git would commit.** This run was of the tree before mutation round 1's fixes
(below), so its figures are not the final tree's; CI's are.
- Six steps were green, and the 24 cross-platform tests of that tree passed.
- `eph-fs` measured 96.57% (338 of 350) against 96.00% on Windows: the directory sync
  runs there.
- `emit` gave the same tree hash as Windows, `fnv1a64:d4f9dccc93cb6b7d`.

**Mutation rounds** (`cargo xtask mutants <crate>`, spec `.cargo/mutants.toml`, each
with its control: one shard, no tests, every viable mutant must be missed):

| Round | Mutants | Caught | Missed | Timeout | Unviable | Control | Verdict |

`eph-schema` is re-run because `home.rs` is new in it. Round 1's 15 findings over
`eph-fs`, and how each was answered:
- **The clock-bounded retry's condition (3 timeouts, 1 missed).** Two changes made it
  retry forever, one by retrying every failure and one by ignoring the budget for a
  hold that never ends; a third halved each wait instead of
  doubling it until the waits were zero and the tests' fake clock never reached the
  budget, and `<` to `<=` changed nothing a test saw. The loop is now the fixed `WAITS`
  schedule (§3.1), which has no condition to change, and tests pin its waits, its sum
  and its attempt count.
- **A not-found guard in `home::open` (1 missed)** that no test could tell from the
  `create_dir_all` after it. It was deleted (§3.3).
- **The newest-segment search (1 missed)** compared first `seq`s by hand, and `>` to `>=`
  changed nothing, because two segments never share a first `seq`. It is now
  `max_by_key`, which has no comparison to change.
- **Untested, now tested (8 missed):** `ROTATE_AT_BYTES`' value, 4 MiB (2); a read
  error other than not-found returning `Err` instead of reading as empty, in each of the
  three readers (3); `authority.json`'s seeded-from version, through its drift report
  (2); and `root_from_env`, through a test that it agrees with `resolve_root` over the
  real environment (1).
- **One exclusion (1 missed),** `sync_dir -> io::Result<()> with Ok(())`, recorded in
  `.cargo/mutants.toml` with its reason. The directory sync's only effect is durability
  across a power cut. A process reading the directory back sees the rename either way,
  so no test can observe it, and on Windows its body does not run.

floor seeded from three runs per platform.
