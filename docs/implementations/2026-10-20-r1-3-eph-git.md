# R1.3 — `eph-git`: the single committer, its lock, and the agents' worktrees

**Date:** 2026-10-20 · **Branch:** `feature/r1-3-eph-git` · **Package:** R1.3

- *R1.3 — Architect decisions*: the committer's OS lock, and hermetic Agora git;
- *R1.3 — Architect decisions, after review*: a deadline-killed git is recorded until
  R2, a detached commit nothing holds is kept, and the TypeScript build is patched;

**Gymnasium:** GYM-013 (the rewrite)

## 1. Problem / motivation

Invariant 4 says only the main process commits to the Agora, and ADR-0004 explains why:
with up to thirty agent processes, concurrent git calls corrupt `.git/index.lock`. The
TypeScript build kept that promise with one promise chain in `agora.ts`, and kept every
git start in `git.ts`. This package is that layer in Rust, and the gate's invariants
check already refuses a git start in any other crate.

Two premises the TypeScript build only assumed are now enforced:

- **The stale-lock rule.** Removing a stale `index.lock` is safe only if nothing else
  commits to the same Agora. One harness per home (ADR-0034's probe) arrives in R7. The
  Architect decided that the committer holds its own OS lock.
- **The host's git configuration.** The TypeScript build overrode identity, signing,
  hooks and housekeeping on the command line, and read everything else from the user's
  configuration. So a global `excludesFile` could hide an Agora file from `add -A`, and
  that work would never reach history. The Architect decided that the Agora's git reads
  no machine configuration.

Two read-only reviews ran before the mutation rounds: a design-fidelity review against
the documents, and an adversarial refutation pass that measured its claims with real
git. Between them they found that several sentences of the first build were false. §5
says what each changed, and three of them went back to the Architect.

## 3. Implementation approach

### 3.1 The runner

`Git::run(cwd, args)` starts `git <overrides> <args>` and returns a `GitResult`: stdout,
stderr, and `code: Option<i32>`, where `ok()` means `code == Some(0)`. It never panics
and never returns an error. Each of these is `code: None`, with a sentence appended to
`stderr`:
- a git that could not start;
- a git stopped at its deadline;
- a status that could not be read;
- output that never arrived.

Every call:

- **is pinned to `cwd`.** It drops `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`,
  `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`,
  `GIT_CEILING_DIRECTORIES`, `GIT_NAMESPACE` and `GIT_QUARANTINE_PATH`, compared in upper
  case as Windows compares them. A harness started from a git hook or an agent's shell
  would otherwise run against someone else's repository.
- **asks nothing and holds nothing optional.** stdin is closed, with
  `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0` (so `status` takes no `index.lock`) and
  `GIT_LITERAL_PATHSPECS=1`.
- **carries the TypeScript build's command-line overrides:** `commit.gpgsign=false`,
  `core.hooksPath=/dev/null`, `maintenance.autoDetach=false` and `gc.autoDetach=false`.
  They win over the repository's own config, which every profile still reads.
- **is never stalled by a full pipe.** Both pipes are read on threads while the deadline
  is watched.
- **opens no console** on Windows (`CREATE_NO_WINDOW`).

**The deadline bounds the call, not git.** At 20 s (at most one hour, clamped) the
process the runner started is killed. On Windows that is often Git for Windows'
`cmd\git.exe` wrapper, whose real git keeps running (measured). On POSIX the kill
does not reach git's own children. Killing the whole tree is R2's. Output is waited for
until the deadline plus 500 ms, and output that never arrives fails the call, because a
grandchild holding the pipes would otherwise turn an empty `status` into "nothing to
commit".

There are two profiles:

- **`Git::agora()`** reads no machine configuration. Concretely it:
  - sets `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null` and
    `GIT_ATTR_NOSYSTEM=1`;
  - adds `-c core.excludesFile=/dev/null -c core.attributesFile=/dev/null
    -c core.fsmonitor=false`, because with the keys unset git falls back to the XDG
    `git/ignore` and `git/attributes`;
  - drops every config-value variable, plus `GIT_TEMPLATE_DIR`, `GIT_DEFAULT_HASH`,
    `GIT_DEFAULT_REF_FORMAT` and `GIT_ATTR_SOURCE`;
  - sets the identity through `GIT_AUTHOR_*` and `GIT_COMMITTER_*`, which outrank
    configuration, and drops the two date variables.

  It is crate-private, because any other git on the Agora would bypass the queue.
- **`Git::target()`** reads the user's configuration. `without_machine_config()` gives it
  the Agora's isolation, and every test that runs git uses that.
  `with_environment(vars)` starts git with exactly `vars` inherited, which is how a test
  plays a hostile host.

### 3.2 The committer

`Committer::open(root, hooks)`, in order:

1. Makes `root` absolute and creates `.git`. A `.git` that is not a directory is
   refused.
2. Takes `eph_fs::lock::Exclusive` on `.git/ephesus-committer.lock`, asking again over
   `LOCK_WAITS` (150 ms) while it reads as held. On POSIX a lock released a moment ago
   can still read as held while a process another thread forked has not exec'd. A
   lock still held after the waits is `OpenError::Held`, which names the fix.
3. Runs `git init --template= -b main` when `.git/HEAD` is absent. So only the lock's
   holder can make the repository, a `.git` a crash left half made is finished, and no
   template can plant hooks, an `info/exclude` or a `core.fsmonitor`.
4. **Judges a killed harness's `index.lock`.** While it exists, open waits over the retry
   schedule, so a git still running for the dead harness can finish. Then it removes a
   lock that outlived the schedule. The answer is `Opened::index_lock`: `Absent`,
   `Removed`, or `Stuck` with the OS's reason.
5. Starts one thread that owns the runner, the hooks and the lock.

Every public call is a message to that thread: `commit`, `commit_soon`, `reconcile`
(a commit under `reconcile uncommitted work after restart`), `drained`, `head` and
`is_dirty`. So two git calls on the Agora never run at once.

The thread takes one request, then everything already queued behind it. Consecutive
commits are one batch, and a query lands the batch before it is answered.

Each attempt runs these steps:
1. `add -A`;
2. `status --porcelain`, where nothing staged is a landing that names the current
   `HEAD`;
3. writes the message to `.git/EPHESUS_COMMIT_MSG` with `write_atomic`;
4. `commit -F` that file.

A failed git result is retried after the next wait of `RETRY_WAITS` (25, 50, 100,
200 ms). Before each retry, an `index.lock` older than the 20 s deadline is removed, and
a younger one, which is someone else's, is left alone. A fault hook that refuses aborts
the batch at once, with its reason word for word and no retry.

A failure goes back to every subject in its batch, either to a `Ticket` or to the record
of failures nobody waited for:
- a `Ticket` gets a `CommitFailure` (`{subject, reason}`, the renderer's existing
  contract);
- `commit_soon`, a dropped ticket, a queue that has stopped, and the landing `Drop`
  waits for are reported through `Hooks::reporting_to`, and the latest 50 are kept in
  `failures()`.

Dropping the committer lands its queue, then releases the lock.

### 3.3 Worktrees and remotes

`Worktrees::create(plan)`:

1. Refuses a repository at or under the Agora's root, and a worktree path inside the
   Agora.
2. Asks git who the repository is (`rev-parse --path-format=absolute --git-common-dir`,
   and `--show-toplevel`). A target that is not a repository is refused, and so is one
   whose git directory holds `ephesus-committer.lock`: the Agora reached any other way.
3. Refuses a path inside the target's working tree.
4. Reuses an existing path whose common directory equals the target's, where it stands,
   on whatever branch it is on. A detached checkout reads as `detached at <sha>`.
5. Uses any other existing path only if `path_is_vacant` finds an empty real directory,
   after a `worktree prune`. Otherwise it is refused, with the recovery sentence for a
   checkout of another repository or for a plain directory.
6. Makes a missing branch with `-b`.

`state` runs `status --porcelain --untracked-files=all`. `remove` never forces. It keeps
a worktree with changes, and a detached worktree whose commit no branch, remote branch
or tag holds, whose reason names the sha and `git branch <name> <sha>`. Otherwise it
runs `git -c status.showUntrackedFiles=all worktree remove`, prunes, and sweeps an empty
leftover directory. Ignored files go with a removed worktree, as git does.

`read_remotes` splits each line at the tab and at the last space, so a URL may hold
spaces. A failure is said in git's first line, or in a plain sentence when git printed
nothing.

## 4. Mathematical / statistical details

**The retry schedule.** The waits are $w = (25, 50, 100, 200)$ ms, so there are at most
$1 + |w| = 5$ attempts and at most

$$\sum_i w_i = 375\ \text{ms}$$

of waiting before a commit gives up. Open's wait for a live git uses the same schedule.

**The age rule.** Let $a$ be an `index.lock`'s age, its file's modification time
subtracted from now. A retry removes it when $a \ge T$, where $T = 20$ s is the runner's
deadline. Git creates the lock at the start of an operation and writes it at the end. So
a deadline-killed git of the committer's own leaves either an old lock, cleared on the
next retry, or a young one, which waits until $a \ge T$ and is cleared by a later batch.

**The failure record** keeps the most recent $N = 50$. After $k$ failures it holds
failures $\max(1, k - N + 1)$ through $k$.

## 5. Design decisions

- **The committer's OS lock (Architect).** The OS releases it when the process dies, so
  it has none of the costs ADR-0034 named against a pidfile. The lock file is never
  created through `write_atomic`, because a rename swaps the file a lock is held on.
- **Measured: the share mode.** With std's default share mode another process can delete
  a held lock file on Windows, and a new file then takes a second, independent lock.
  `Exclusive` denies delete sharing, and a test shows the delete refused with error 32.
- **Measured: what a refused delete of `index.lock` means.** A live `git add` on Windows
  holds `index.lock` without delete sharing, so a delete is refused with EBUSY (32). A
  `git commit` waiting on its editor has closed the file, so a delete succeeds. A
  refusal therefore proves some process holds the lock, and a success proves nothing.
  The Windows test stands in `Exclusive` for that holder, and says so.
- **What the reviews changed, and why.**
  - *The order of open.* A retry 25 ms after a first failure could remove a live
    orphan's lock before anything had waited. The lock is now judged at open, before
    any commit, and a retry removes only a lock older than the deadline.
  - *Hermetic, completely.* The XDG ignore and attributes files reached the Agora, and a
    planted ignore hid a file from `add -A` (measured). `GIT_TEMPLATE_DIR` rewrote `.git`
    at init, and a planted `core.fsmonitor` then ran on every `status` (measured). Both
    are closed and tested two-sided: the same plant reaches a runner that reads it.
  - *Untracked work a repository hides* (FR-1.5). With `status.showUntrackedFiles=no`,
    `git worktree remove` deleted an agent's untracked file (measured on 2.53).
  - *Repository identity.* A plan naming a repository's subdirectory let a worktree land
    inside the working tree, and refused the agent's own checkout on respawn.
  - *Large batches.* A message past about 32,000 characters can never be passed on a
    Windows command line, so it goes through `-F`.
  - *A dropped ticket* lost its failure silently. Now it is reported and kept, and the
    outcome types are `#[must_use]`.
  - *Push reporting.* The TypeScript build's `onCommitError` reported give-ups. Here
    `Hooks::reporting_to` does, so R1.4 can raise `agora/commit`.
  - *Fault seam honesty.* The fault type (`Faults` then, `Hooks` now) lost its
    `Default`, which made `none()` and `default()` one value twice (memory: *an
    equivalent mutant is a design smell*).
- **Three questions went to the Architect after review**, each answered with the
  recommended option:
  - A deadline-killed git is recorded as not guaranteed dead until R2's tree kill.
  - A detached commit nothing holds is kept.
  - The TypeScript build's untracked-work loss is patched in `fix/worktree-untracked-files`.
- **One thread, not an async task.** The queue is serial by nature, and tokio's row is
  R3's.
- **The kills are real.** The test binary runs itself again as the harness, and that
  process dies:
  - by its own `exit` at each of the four fault points;
  - or killed by the OS at random moments of a commit loop.

  The TypeScript S-BLACKOUT injects a throw and abandons the object.
- **Residuals, stated** (DECISIONS-LOG, *R1.3 — implementation*, item 18):
  - on POSIX, a lock file deleted by hand or a `.git` moved while it is held;
  - NFS lock emulation;
  - `safe.directory` under the hermetic profile;
  - a link planted between the vacancy check and `worktree add`;
  - a repository-wide `worktree prune`;
  - a 20 s deadline on a large `worktree add`;
  - a panicking hook losing queued work;
  - the kill tests' limit: fault-point exits land between git calls.

Each finding, and how it was answered:
- **Round 1's timeout:** `Faults::check` returning `Ok` left the batching test blocked on
  a channel. Every wait in a test is now bounded (`CHILD_PATIENCE`, 10 s, well inside
  the round's per-mutant timeout). Its survivor, `Faults::none` replaced by
  `Default::default()`, was one value spelled twice, and `Default` was removed.
- **Round 2's timeout:** `while kept.len() > 50` flipped to `<` looped forever. One
  failure is added at a time, so it is now an `if`, which no flipped condition can turn
  into a loop.
- **Round 2's survivors:**
  - dropping `GIT_CONFIG_KEY_`/`VALUE_` changed nothing, because git reads them only
    through `GIT_CONFIG_COUNT`, which is dropped, so the redundant drop was deleted;
  - `self.identity && …` flipped to `||` would have dropped the Agora's whole
    environment unseen, so a test now shows each profile keeping what it does not name;
  - `MAX_TIMEOUT`'s `60 * 60` was unpinned, so a test pins it;
  - `stdout_arrived && stderr_arrived` flipped to `||` was unseen, so a test now loses
    each pipe alone;
  - the `NotFound` arm at open's lock removal was reachable only by a race no test can
    stage, so it was removed;
  - `0x1 | 0x2` flipped to `^` is the same 3 (`eph-fs`), so it is now written as 3.
- **One exclusion:** `replace + with - in drain_until`, the 500 ms output grace, recorded
  in `.cargo/mutants.toml` with its reason. Only a test timing a pipe's close to within
  the grace could see it, which flakes on a loaded machine. The cases either side of the
  window are tested.
- **Round 3's three timeouts** were the machine, not the mutants: 366 MB free, 33.7 GB
  committed and builds of 44 to 212 s (normally 1 s). Each of the three is caught by an
  existing test. Round 4 ran on the final tree with 2 GB free and was clean.

**CI found two defects no local run could.** Run 39462842597:
- *Ubuntu.* A committer dropped a moment before another opened read as held. On POSIX
  a process another test thread forks holds a copy of every open file until it execs.
  Open now asks again over `LOCK_WAITS` (150 ms) before refusing.
- *Windows.* The many-callers test writes files while commits run, so an `add -A` met
  one mid-rename and was retried. The test's claim of a single attempt was too strong
  and was removed: the retries exist for exactly this.

On run 39465824068 (`8e13242`), every test passed on Linux, macOS and Windows in each
attempt.

Run 39469986385, on the commit carrying the floor, found a third, on Windows: a timing
assumption in a test.
- `open_lets_a_live_git_finish…` deleted its stand-in lock at 200 ms, 175 ms before the
  end of open's wait. On a slow runner the two deletes raced. A file whose delete is
  still pending, or which a scanner holds open, refuses a second delete with error 5,
  and open answered `Stuck`, which is the honest answer to that race.
- The stand-in now deletes at 30 ms. This test-only change follows round 4, and the
  round does not rest on it: the mutants of open's wait loop are also killed by
  `open_removes_a_lock_that_outlived_the_schedule…`, which asserts `Removed`.
- The behaviour this records: on Windows, a lock another process is deleting can read
  as `Stuck` for as long as its delete is pending. That is a transient report, which
  the commit's retries and the next boot clear.
