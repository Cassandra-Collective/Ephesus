## 1. Problem / motivation

`scripts/mutate.cjs` is the evidence every M9 package owes (M9-PLAN §6): a round from a
checked-in spec, certified by a control. When #71 merged on 2026-10-11, its review had found three
lines nobody's test defended. The Architect chose to land #71 with three doc corrections
and carry these to a follow-up (DECISIONS-LOG 2026-10-11, "at review before merge"):

1. **The last mutant's restore guard was unkilled.** Deleting
   `if (unrestored !== null) throw unrestored` left all 87 tests green. Every integration
   case that failed a restore also had a run fault, so it took the combined branch.
2. **The retry wait was untested.** Every test round passed `--retry-wait 0`, so deleting
   the `Atomics.wait` call kept "waits out a refusal" green. Yet TEST-STRATEGY §10 and the
   script's header both say "retried after a wait".
3. **The mutant was written before the `try`.** A write that fails after truncating the
   file (ENOSPC, EIO) left it truncated and never restored. The runner's docstring says
   every mutant is put back "before this returns or throws".

The first two were reproduced on `main` before anything was planned. A round whose
control survived showed both deletions surviving all 87 tests (§6). The third is
visible in the source.

The same review raised five items for the Architect, plus two stale texts:

- **Controls-only specs:** a spec of controls only printed "ROUND OK — 0 of 0" and exited 0.
- **Unnamed kills:** kill lines named no test, so a baseline test timing out under load
  scored as a kill nobody earned.
- **Pathspecs:** git read round file names as patterns.
- **Anchor rot:** the approved proposal said anchor rot fires "in CI", and nothing in CI
  read a spec.
- **Linked `node_modules`:** a symlinked `node_modules` on linux or macOS stops a round
  from starting.
- **Stale texts:** the old record's "CI has not run this branch", and a test title that
  over-claimed against known limit 2.

## 3. Implementation approach

### 3.1 Gap 1 — a restore that did not hold after a clean run

`restore()` puts the file back with `git checkout --`. It then proves the restore twice: by
the round files' hashes, and by `git status` over them. When the run before it had
faulted, both failures are reported together. When the run was clean, one line reports
the restore: `if (unrestored !== null) throw unrestored`.

Without that line nothing else does. A later mutant on another file would notice the
stranded file through its own drift check. The last mutant has no later one. A later
mutant on the same file restores through the same deleted line.

**The fixture.** It reaches this deterministically. A mutant exports `marker = 'STAGE'`.
The fixture's test then runs `git add mod.mjs` (with an explicit `cwd`) and throws. Every
post-run check passes:

- the other round files hash as at the start;
- the target holds exactly the mutant;
- the staged entry `M  mod.mjs` names a round file, which `treeChanges` leaves to the
  hashes.

`git checkout --` restores from the index, and the index now holds the mutant. So the
restore check sees `mod.mjs` drift and `M  mod.mjs` in `git status`. With the guard the
round is INVALID: "M1: the restore did not hold (mod.mjs; M  mod.mjs)". Without it, M1
is scored killed (its test threw) and the round says ROUND OK with the mutant still
staged.

The test also asserts that the tree is left as it is: `M  mod.mjs`, with the mutant in
the file. The round reports a tree it cannot trust; it does not repair one.

### 3.2 Gap 2 — the retry wait, timed inside the tool

Timing the whole round cannot see a one-second wait, because each vitest takes
seconds. Timing from the global setup cannot either, because the gap would include
vitest's own start-up. The one gap that isolates the wait is the tool's own: from the
moment one vitest's `spawnSync` returns to the moment the next one's begins.

`PROBE` is written into its own temp directory, never the fixture, whose tree must stay
clean. It is loaded with `node --require <probe> scripts/mutate.cjs …`. A child process
does not inherit its parent's `execArgv`, and `round()` already strips `NODE_OPTIONS`, so
the nested vitest never loads it. With `EPH_PROBE_STAMPS` set, the probe replaces
`child_process.spawnSync` before the tool loads. It then appends
`{ start, end }` for each vitest run, in `performance.now()` of the tool's process. The
tool binds `spawnSync` at load time, after the probe has replaced it.

"Waits out a refusal" now passes `--retry-wait 1`. It asserts four runs (the refused
baseline, the baseline that answered, the control, M1), and that the gap between the
first two is at least 950 ms.

### 3.3 Gap 3 — a write that fails part-way is restored

`fs.writeFileSync(target, mutated)` moves inside the `try`, so a throw from it becomes the
round's fault and the restore runs before it is reported. Computing the mutant
(`mutate()`) stays outside: it is pure and writes nothing.

The same probe injects the failure. With `EPH_PROBE_FAIL_WRITE` set, a buffer holding
that text is written half-way, and then the probe throws an `ENOSPC`-coded error: the
shape a full disk leaves.

The message is unchanged in both versions: "the harness failed: Error: ENOSPC …", exit
2. What differs is the tree. The test asserts that `mod.mjs` is byte-equal to the
original and that `git status` is empty. Before the move, the file kept half a mutant.

### 3.4 A spec of controls only is refused

`specProblems` adds "every mutant is a control: add at least one real mutant …" when no
mutant is a non-control. A spec with no mutants at all is already refused, so this fires
only on a non-empty list. `--check` runs `specProblems`, so the CI step refuses such a
spec too.

### 3.5 The kill rule: timeouts earn nothing, and a kill names its killers

**What the report holds.** Measured on vitest 4.1.11, the JSON report never says "timed
out". `@vitest/runner`'s `makeTimeoutError` builds the error with the right message. It
then sets `error.stack = stackTraceError.stack.replace(error.message,
stackTraceError.message)`, the reverse of its siblings (`makeAroundHookTimeoutError`,
`copyStackTrace`). The stack therefore keeps its placeholder, and the JSON reporter
writes `e.stack || e.message`. A timed-out test or hook is `failed` with a first message
line of `Error: STACK_TRACE_ERROR`; the default reporter prints the real text.

Reading `@vitest/runner` and `vitest`'s dist, no other path in 4.1.11 reports that first
line. `TIMEOUT_LINE` matches it, or `Error: Test|Hook timed out in Nms.` exactly, which
is what a vitest that fixed the bug would write.

That is vitest's own test or hook timeout and nothing else. `vi.waitFor` and
`vi.waitUntil`, an around-hook's timeout, and this repository's own deadlines still score
as kills when they expire under load. The kill line names them; the round does not
refuse them. The Architect chose to record this as TEST-STRATEGY §10's known limit 12
rather than widen the match.

**How `classify` uses it.** `filesOf` marks a test `timedOut` when it has at least one
message and every message's first line matches. Under a mutant, `classify` then checks in
this order (step 2 before step 3 has its own unit case and mutant):

1. A killing test that did not time out → a kill, carrying those tests and the count that
   only timed out.
2. Otherwise a listed file that could not load → a file kill, as before.
3. Otherwise killing tests that all timed out → INVALID with `retry: true`, so
   `runAnswered` waits and runs again as it does for a refusal to start.
4. Otherwise any other failure → INVALID, as before.

**Unchanged.** A timeout at the baseline is still a red suite, which stops the round. A
`beforeAll` timeout skips its tests and fails the file with an empty message; that run
was INVALID before and stays so, not retried.

**The pin.** An integration case on the real vitest pins the shape: a test with a 1 s
timeout that, under the mutant, waits 5 s. If a vitest upgrade changes the shape, the run
reads as an ordinary kill and that case fails. It cannot silently turn the rule off.

**The kill line.** `killedBy(verdict)` formats it: `N tests failed: a; b; c +k more;
m more only timed out`, or, for a file kill, the file's first message line as before.

### 3.6 Git reads every name literally

`git()` prepends `--literal-pathspecs`. It applies to every call: `checkout`, `status`,
`ls-files`, `hash-object` (whose arguments are paths anyway), `rev-parse`.

The integration case names a mutated file `data[1].txt` next to a tracked `data1.txt`,
which the pattern also matches. Under the mutant, the fixture's test appends to
`data1.txt`. The run's fault names it (` M data1.txt changed while the suite ran`), and
the restore puts back `data[1].txt` alone. `data1.txt` keeps what the run wrote, which is
what the message tells the reader to inspect. Read as a pattern, the restore reverted
both and left the tree clean.

### 3.7 The CI step (GYM-012)

The step sits directly after `Install`, where the checkout is clean and `npm ci` has
written only the ignored `node_modules`. It globs `test/mutation/*.json` with `nullglob`,
fails if there is none, and runs `node scripts/mutate.cjs <spec> --check` for each,
stopping at the first failure. `--check` runs no test and needs no `node_modules`: it
validates, checks the tree and the files, and counts anchors.

On the merged tree it checks two specs. Besides `gym-008.json` there is
`readme-current.json`, which #73 brought in. Since `--check`'s refusals now sit inside a
required check, a future change to what they refuse takes its own Gymnasium row
(Architect, 2026-10-11).

### 3.8 `.gitignore`

`node_modules/` becomes `node_modules`. A trailing slash makes a pattern match only a
directory, and git does not follow a symlink. A linked `node_modules` on linux or macOS
was therefore untracked, and the round's clean-tree check refused to start. On win32 a
junction reads as a directory, which is why this machine never saw it.

## 4. Mathematical / statistical details

**The kill rule as sets.** For one mutant run, let:

- B be the tests that passed at the baseline;
- F the tests that failed in the run;
- T ⊆ F the failed tests whose every message's first line is a timeout's;
- U the listed files that failed with no test (could not load).

From these, let K = F ∩ B be the killers and E = K \ T the earned killers. The verdict,
in order:

- **kill:** E ≠ ∅, carrying E and |K| − |E|;
- **file kill:** E = ∅ and U ≠ ∅;
- **INVALID, retried:** E = ∅, U = ∅ and K ≠ ∅, so every killer only timed out;
- **INVALID, not retried:** any other failure.

A pass still needs every test in B to pass again. The kill rule before this change was
the same with T = ∅.

**The wait threshold.** For runs i and i+1, let g = start(i+1) − end(i), both read from
`performance.now()` in the tool's process. With `--retry-wait` w seconds, the tool calls
`Atomics.wait` for 1000·w ms between them, so g ≥ 1000·w ms less the timer's rounding.

The test uses w = 1 and asserts g ≥ 950 ms. The 50 ms covers that rounding. Without the
wait, g is the tool's own work between the runs: scoring the report, removing the
report's temp directory, printing the retry line, making the next temp directory. That
was measured three times on 2026-10-11 by running the test against the mutant that
deletes the wait (win32, node v20.16.0, 1.76 GB free): 7.28, 5.28 and 9.40 ms. The
threshold is about 100 times the largest observed gap. A single 1 s wait adds about one
second to the suite.

## 5. Design decisions

Each decision below was the Architect's, and DECISIONS-LOG 2026-10-11 records the options
offered. In brief:

- **Controls-only specs:** refused in this change, over refusing later or recording it as
  allowed.
- **Kill naming and timeouts:** a kill names its killers, and a run whose only killers
  timed out is INVALID and retried. Rejected: naming only (recommended), deciding later,
  leaving it, and not retrying. The Architect was told a hang-only mutant then cannot be
  killed.
- **Pathspecs:** `--literal-pathspecs` on every call, over a later change or a recorded
  limit.
- **Anchor rot:** a `ci.yml` step under GYM-012, filed and approved before the step.
  Rejected: a vitest case over the pure checks, a later package, and correcting the
  proposal's wording.
- **Linked `node_modules`:** the slash dropped from `.gitignore`, over a §10 note with an
  `info/exclude` workaround.
- **The retry wait:** pinned through a `--require` probe, over an injectable
  `{ run, wait }` seam on `runAnswered` with a real-sleep test. The probe keeps the tool
  free of test seams, and gap 3 needed it anyway.
- **Ledger:** only the CI step takes a row. The tool's changes are GYM-008 follow-ups,
  because the tool is author-run evidence, not a gate.

After an independent design review of the branch (DECISIONS-LOG 2026-10-11, "reviewed
before the self-round"):

- **Other deadlines:** they are known limit 12, over widening the match to vitest's other
  deadlines or to the repository's own.
- **Future changes to `--check`:** a change to what it refuses takes its own row, over
  only changes to the `ci.yml` step taking one.
- **TEST-STRATEGY §8:** its "Weekly: … mutation (rotating)" line is left as it is and
  flagged (*Not proven*), over annotating or removing it.
- **The first self-round:** the round at `ec758f2` was stopped, so that one round runs on
  the final commit, over letting it finish and running a second, or supplementing it with
  a smaller one.

The mechanical choices made here:

- **The write failure keeps its message.** A failed write is not an `Invalid`, so it
  still reads "the harness failed: Error: ENOSPC …" with the stack. Wrapping it in a
  friendlier sentence was not asked for, and the exit status (2) is already right.
- **A file kill outranks a timeout-only run.** A listed file that cannot load depends on
  the line whatever the load is. A timeout does not. The design review found this order
  untested, and it now has a unit case and a mutant (`K-timeouts-before-file-kill`).
- **`timedOut` names only the two flags.** The function is `onlyTimedOut`, and the
  verdict's count is `timedOutKillers`. Before, one name had stood for four things: the
  function, the run's `--timeout` flag, the per-test flag and the count.
- **`killedBy` is a pure, exported function**, unit-tested like `classify`. The "+k more"
  form would otherwise need a fixture with four failing tests.
- **The probe matches vitest runs** by `command === process.execPath` and a
  `--reporter=json` argument, so the tool's git calls are not stamped. The test asserts
  the run count, so a tool that stopped starting vitest through `spawnSync` would fail
  loudly rather than measure nothing.
- **No mutant for the `git status` half of the restore check.** The staged-mutant case
  now asserts that half's line, but the hashes catch the same restore. A mutant there
  would be killed by the message's wording, not by a verdict the hashes miss, and claiming
  it would over-claim. The old record's *Not proven* keeps it.
