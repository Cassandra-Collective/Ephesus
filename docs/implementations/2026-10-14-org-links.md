# The repository moved to Cassandra-Collective, and its links follow

**Date:** 2026-10-14 · **Branch:** `docs/org-links` · **Issue:** #78

---

On 2026-10-14 Ephesus moved from the personal account `mertefesensoy` to the
organisation `Cassandra-Collective`, with the other projects of the collective.
GitHub redirects the old path, but only until a repository is created there, so
every link that means "this repository" now names the organisation.

## What changed

52 links in 22 files, all of the form `https://github.com/mertefesensoy/Ephesus...`
becoming `https://github.com/Cassandra-Collective/Ephesus...`:

| Where | Links |
|---|---|
| `README.md` (CI badge, `git clone`), `CONTRIBUTING.md`, `SECURITY.md`, `.github/ISSUE_TEMPLATE/config.yml` | 9 |
| `docs/THREAT-MODEL.md`, `docs/progress/M3.md`, `docs/progress/M4.md`, two implementation docs | 18 |
| The website sources: `site/src/layouts/Base.astro` (including the `codeRepository` structured-data field), eight page templates and four blog posts | 25 |

The replacement was scripted over every tracked text file, then re-grepped.

## What deliberately did not change

- **`test/shared/repo-remote.test.ts`.** Its seven `mertefesensoy/Ephesus`
  strings are fixtures for the remote-URL parser, not links; the test is about
  parsing, and any owner name serves.
- **Dated records of where something ran.** "The driver pointed at
  `mertefesensoy/Ephesus`" in the M7 records and the decisions log was true on
  that day.
- **The two social-card SVGs** (`docs/brand/ephesus-social-card.svg` and its copy
  `site/public/img/social-card.svg`). They draw the URL as text at 18 px in IBM
  Plex Mono, starting at x = 620. A monospace character is 0.6 em, so the new URL
  makes the line 57 × 10.8 = 615.6 px long, ending near x = 1236, about 107 px
  past the right edge of the wordmark and rule that every other line aligns to
  (x ≈ 1129). Fitting it is a layout decision for the design system, not a link
  fix. The cards, and the social preview image already uploaded to GitHub from
  them, keep the old path until that is decided.

## Not covered

The website changes reach ephesushq.com only when the site is next built and
deployed. Links inside existing issues and pull requests still use the old path
and rely on the redirect.

## Evidence

- Re-grep after the change: `git grep -i "github.com/mertefesensoy/Ephesus"`
  matches only the two card SVGs and the test fixtures listed above.
- Every changed line differs only in the URL (39 lines in 22 files, plus this
  document), checked by mapping each new line back to the old owner and comparing.
  Three CI-run links in `docs/progress/M4.md` spelled the repository `ephesus` in
  lower case and now read `Ephesus`; GitHub paths are case-insensitive. No application source or test changed, so typecheck, lint and tests
  are unaffected; CI runs on the pull request.
